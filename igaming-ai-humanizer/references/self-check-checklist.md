# Final check

1. Lexicon: any matches against `en-markers.md`, `igaming-lexicon.md`,
   `ru-markers.md`? → judge each in context first. Revise only if it's an
   unsupported evaluative claim, a generic phrase with no specific
   feature/benefit behind it, a repetition, or off-tone wording. If it
   states a real fact or function, leave it — a list match alone isn't a
   reason to rewrite. Where a rewrite is warranted, use a fact you actually
   have; if none exists, ask for one or drop the claim — don't invent a
   number to force a rewrite.
2. Rhythm: sentences/paragraphs all a uniform length? → vary pacing to fit
   the content, without locking onto a new fixed pattern.
3. Em dash: more than 1 per 300–400 words? → cut.
4. Repetition: the same count/shape of items repeated block after block
   with no reason tied to the content? → change it.
5. Lists: did it turn into a listicle instead of running prose, with no
   list requested? → rewrite.
6. Specifics: is there a number/fact/condition backing each claimed
   benefit, and is it real (not invented)? → add a real one or ask the user
   for it.
7. Confidence: does the text smooth over a caveat or condition that's
   actually present in the source material? → keep the caveat in. (Don't
   add a fake one where none exists.)
8. Material facts: compare against the source — are all amounts,
   currencies, percentages, deadlines, wagering requirements, minimum
   deposits, maximum payouts, eligibility/GEO restrictions, and qualifiers
   ("up to", "only", "except", "provided that", etc.) still present and
   accurate? Are required links, verbatim phrases, and mandatory structure
   intact? → restore anything dropped or softened; if the source was
   contradictory or unclear, flag it instead of guessing.
9. Portability: could this text drop into any similar product unchanged? →
   add product-specific detail.
10. Tells: "I hope this helps", self-references to being AI-generated,
    placeholders like "[insert example]"? → remove.

Return only the finished text after this check — no notes, no summary of
what changed, no mention that a checklist was run.
