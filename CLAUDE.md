# CLAUDE.md — IGTL-SKILLS

Инструкции для Claude Code при работе с этим репозиторием. Читай целиком перед
любым изменением.

## Что это за репозиторий

`igamingtextlab/IGTL-SKILLS` — публичный репозиторий бесплатных Claude Skills
от iGamingTextLab. Это лид-магнит: посетитель скачивает скилл, а README ведёт
его на платформу (регистрация с $40 кредита) и на сайт.

Отсюда две цели, и обе важны одинаково:

1. Скиллы должны скачиваться и устанавливаться без ошибок.
2. Каждая ссылка на наш сайт и платформу должна быть с UTM-метками, а каждая
   ссылка на скачивание — работать.

Репозиторий публичный. Всё, что попадает в коммит (включая этот файл),
видят все. Не коммить токены, внутренние документы, данные клиентов.

## Структура

```
IGTL-SKILLS/
├── CLAUDE.md                     # этот файл
├── README.md                     # публичная страница (маркетинг + скачивание)
├── LICENSE                       # CC BY 4.0
├── .gitignore                    # исключает dist/
├── scripts/
│   └── build_skills.py           # валидация и сборка .skill-файлов в dist/
├── igaming-ai-humanizer/         # скилл 1 (исходники)
│   ├── SKILL.md
│   └── references/*.md
└── igtl-geo-germany/             # скилл 2 (исходники)
    ├── SKILL.md
    └── README.md                 # посадочная страница скилла на GitHub (в .skill не входит)
```

- **Исходники скилла** — папка в корне репозитория с `SKILL.md` внутри. Она
  лежит в git, чтобы люди могли читать файлы прямо на GitHub.
- **`.skill`-файл** — ZIP-архив этой папки (папка — корень архива). В git он
  **не** коммитится: собирается в `dist/` и прикладывается к релизу.

## Реестр скиллов

| Папка (= `name` в SKILL.md) | Файл в релизе | Впервые в релизе |
|---|---|---|
| `igaming-ai-humanizer` | `iGamingTextLab-ai-humanizer.skill` | v1.3 |
| `igtl-geo-germany` | `iGamingTextLab-geo-germany.skill` | v1.4 |

Этот реестр продублирован в словаре `SKILLS` в `scripts/build_skills.py`.
Меняешь одно — меняй и другое. Скрипт сам падает, если папка скилла есть,
а в реестре её нет.

**Имена.**
- Новые скиллы: папка и `name` — `igtl-<slug>` (kebab-case, латиница, цифры,
  дефисы, до 64 символов), файл релиза — `iGamingTextLab-<slug>.skill`.
- **Никогда не переименовывай существующие файлы релиза и папки.** На имена
  файлов завязаны ссылки скачивания в README, рассылках и постах; после
  переименования они начнут отдавать 404.

## Требования к SKILL.md

Скрипт сборки проверяет это автоматически, но держи в голове:

- Файл начинается с YAML-frontmatter между `---` и `---`.
- Разрешённые ключи: `name`, `description`, `license`, `allowed-tools`,
  `metadata`, `compatibility`. Любые другие — ошибка.
- `name` совпадает с именем папки, kebab-case, до 64 символов.
- `description` — до 1024 символов, без `<` и `>`. Это главный триггер скилла:
  в нём должно быть, *что* делает скилл и *когда* его использовать.
- Ровно один `SKILL.md` на скилл. Дополнительные материалы — в `references/`
  под другими именами.
- `README.md` в корне папки скилла — посадочная страница для людей на GitHub
  (ссылка для рекламы конкретного скилла). Скрипт сборки его в `.skill` не
  кладёт. Ссылки на наши домены в нём — с UTM, как в основном README.

Редакционные правила содержимого скиллов (действуют для всех скиллов):

- В файлах скилла — только операционные инструкции для модели. Без рассуждений,
  истории создания, списков источников ради источников и инструкций для людей
  (исключение — источники, которые модель должна реально проверять, как
  Whitelist в `igtl-geo-germany`).
- Скилл никогда не велит выдумывать факты, цифры, отзывы, тесты, источники.
- Не обещай «обход детекторов» и юридическую гарантию ни в скиллах, ни в README.
- **Не меняй содержание скиллов по своей инициативе.** Правки текста скилла —
  только по прямой задаче. Если видишь проблему — сообщи, а не исправляй молча.

## Сборка

Из корня репозитория:

```bash
python scripts/build_skills.py --check   # только проверка
python scripts/build_skills.py           # проверка + сборка в dist/
```

На Windows может понадобиться `py` вместо `python`. Сторонние библиотеки не
нужны. Скрипт:

- находит все папки в корне, где есть `SKILL.md`;
- сверяет их с реестром `SKILLS`;
- валидирует каждый `SKILL.md`;
- собирает `dist/<имя из реестра>.skill`, пропуская мусор (`.DS_Store`,
  `Thumbs.db`, `__pycache__`, `*.pyc`, папку `evals/` в корне скилла).

Если проверка не прошла — ничего не собирается. Исправь ошибку, не обходи
скрипт ручной упаковкой.

## Релизы — главное правило

**В каждый релиз прикладываются ВСЕ `.skill`-файлы из реестра, а не только
новый или изменённый.**

Почему: ссылки скачивания в README имеют вид
`https://github.com/igamingtextlab/IGTL-SKILLS/releases/latest/download/<файл>`.
`latest` — это самый свежий релиз. Если в нём нет какого-то файла, ссылка на
этот файл отдаёт 404.

**Версии.** Один тег на весь набор скиллов: `v1.4`, `v1.5`, … Новый скилл
или существенная переработка → можно поднять минорную часть (`v1.x`).
Не перезаписывай и не удаляй существующие теги и релизы — на них может кто-то
ссылаться, и в них хранится счётчик скачиваний.

### Порядок выпуска релиза

1. Убедись, что рабочая копия чистая и актуальная: `git status`, `git pull`.
2. Внеси изменения (новая папка скилла / правки README / реестр).
3. `python scripts/build_skills.py` — должно быть `OK` по всем скиллам и
   `BUILT` по всем файлам.
4. Закоммить исходники и README (без `dist/`), запушь в `main`.
5. Подготовь описание релиза в `dist/release-notes.md` (шаблон ниже).
6. Создай релиз со всеми файлами из `dist/`:

   ```bash
   gh release create vX.Y dist/*.skill \
     --title "IGTL Skills vX.Y — <что нового>" \
     --notes-file dist/release-notes.md \
     --latest
   ```

7. Проверь ссылки (раздел «Проверка после релиза»).
8. Покажи пользователю итог: тег, список приложенных файлов, результат
   проверки ссылок.

Создание релиза, push в `main` и любые действия с тегами — **только после
явного подтверждения пользователя** в текущей сессии. Перед этим покажи, что
именно будет опубликовано.

### Шаблон описания релиза

**Skills in this release:**

Описание релиза — на английском. Список скиллов в нём держи полным.

## README

README — посадочная страница. Порядок блоков не меняй без задачи:

1. Логотип, заголовок, подзаголовок.
2. **Кнопки скачивания всех скиллов** — сразу под заголовком, в одном
   `<p align="center">`. Каждая кнопка — бейдж shields.io со ссылкой
   `releases/latest/download/<файл>`.
3. CTA: регистрация и $40 кредита, ссылка на Human-Assisted AI.
4. «Who we are».
5. «Available skills» — по блоку на скилл: описание, дерево файлов, кнопка
   скачивания, установка. Счётчик скачиваний (бейдж
   `img.shields.io/github/downloads/igamingtextlab/IGTL-SKILLS/total`) —
   один на весь репозиторий.
6. «Talk to us» (контакты), «License».

**При добавлении скилла в README:**
- добавь кнопку в верхний блок;
- добавь блок в «Available skills» (перед строкой «More skills land here…»);
- если меняется язык или аудитория скилла — укажи это в описании блока;
- проверь, что имя файла в ссылках совпадает с реестром символ в символ
  (регистр важен).

**Факты о компании** (500+ авторов и редакторов, 14 лет на рынке, 68 языков,
103 рынка, «4x cheaper / 8x fewer errors») — меняй только если пользователь
прямо дал новые цифры. Не придумывай и не «округляй».

## UTM-метки

Обязательны на всех ссылках, ведущих на `igamingtextlab.com` и
`client.igamingtextlab.com`.

Схема:

```
utm_source=github
utm_medium=readme        # в README; в описании релиза — release
utm_campaign=igtl-skills
utm_content=<место>      # уникально для каждой ссылки
```

Текущие значения `utm_content` в README:

| Место | Куда ведёт | utm_content |
|---|---|---|
| Подзаголовок под логотипом | igamingtextlab.com | `header` |
| Главная кнопка регистрации | haai-register | `cta-main` |
| «See how Human-Assisted AI works» | страница HAAI | `haai-link` |
| Регистрация в «Talk to us» | haai-register | `cta-footer` |
| Сайт в «Talk to us» | igamingtextlab.com | `footer` |
| `igtl-geo-germany/README.md`: подзаголовок | igamingtextlab.com | `geo-germany-header` |
| `igtl-geo-germany/README.md`: блок $40 вверху | haai-register | `geo-germany-cta` |
| `igtl-geo-germany/README.md`: регистрация внизу | haai-register | `geo-germany-footer` |
| `igtl-geo-germany/README.md`: сайт внизу | igamingtextlab.com | `geo-germany-site` |

Новая ссылка на наш домен → новое уникальное `utm_content` → добавь строку в
эту таблицу.

**Без UTM** оставляй: ссылки на GitHub (скачивание, Releases), Telegram,
LinkedIn, Instagram, `mailto:`, адрес картинки логотипа.

Порядок параметров: базовый URL, затем `?` (или `&`, если в URL уже есть
параметры), затем метки в порядке source → medium → campaign → content.

## Проверка после любого изменения README или релиза

```bash
# 1. Каждая ссылка скачивания отдаёт файл (ожидается 200 после редиректа)
for f in iGamingTextLab-ai-humanizer.skill iGamingTextLab-geo-germany.skill; do
  curl -sSL -o /dev/null -w "%{http_code}  $f\n" \
    "https://github.com/igamingtextlab/IGTL-SKILLS/releases/latest/download/$f"
done

# 2. Все файлы реестра есть в последнем релизе
gh release view --json tagName,assets --jq '.tagName, .assets[].name'

# 3. Все ссылки на наши домены в README — с UTM (вывод должен быть пустым,
#    кроме адреса логотипа /assets/)
grep -oE 'https://(client\.)?igamingtextlab\.com[^ )"]*' README.md */README.md | grep -v utm_ | grep -v /assets/
```

Если хоть одна проверка не прошла — сообщи пользователю и не считай задачу
выполненной.

## Чего не делать

- Не коммить `dist/` и `.skill`-файлы в git (они в `.gitignore`).
- Не делай `git push --force`, не переписывай историю `main`.
- Не удаляй и не перезаписывай существующие релизы и теги.
- Не переименовывай папки скиллов и файлы релизов.
- Не публикуй релиз только с одним новым файлом.
- Не меняй содержание скиллов, факты о компании и лицензию без прямой задачи.
- Не вставляй токены и пароли в файлы, команды или коммиты. Доступ к GitHub —
  только через `gh auth login`.

## Типовые задачи

**«Добавь новый скилл»** (пользователь даёт папку или архив):
1. Положи папку в корень. Если `name` или имя папки не по правилам —
   предложи исправление и спроси, прежде чем менять.
2. Добавь скилл в реестр (этот файл + `SKILLS` в скрипте).
3. `python scripts/build_skills.py`.
4. Обнови README (кнопка вверху + блок в «Available skills»).
5. Покажи план релиза, после подтверждения — коммит, push, релиз со всеми
   файлами, проверка ссылок.

**«Обнови скилл X»:**
1. Внеси правки в папку скилла.
2. Сборка, коммит, push.
3. Новый релиз `vX.Y` со **всеми** файлами; в описании — что изменилось.

**«Проверь, всё ли в порядке»:** выполни раздел «Проверка после…» целиком,
плюс `python scripts/build_skills.py --check`, и отчитайся по пунктам.
